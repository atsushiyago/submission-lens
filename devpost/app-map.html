Project reference

Submission Lens

Paste hackathon rules, analyze them into grounded organizer requirements, then track them alongside general submission safety checks. The page and one server-side API route run together on a Cloudflare Worker with Static Assets.

One action through the app

The Worker asks Gemini for schema-constrained JSON, validates the parsed result, and checks each excerpt against the pasted text. An unmatched excerpt is suppressed and the item becomes “Needs review.” The browser only receives validated checklist data.

Reference route through the code

This route is a map for future changes; the build used a prior evidence-based review rather than a separate code-tour exercise.

  1. src/App.tsx — App and handleAnalyze own in-memory input, errors, checklist state, and the main page composition.
  2. src/lib/analyze.ts — analyzeRules sends the browser request and validates the returned response shape.
  3. worker/index.ts — handleAnalyze calls Gemini; src/shared/analysis.ts parses the structured JSON and verifies source excerpts. The checklist components render the returned requirements and built-in checks.

To change this, start here

Organizer categories or response validation: src/shared/analysis.ts

Gemini prompt, API call, and controlled errors: worker/index.ts

Built-in safety items: src/data/safetyChecks.ts

Checklist sections and progress behavior: src/App.tsx and src/components/

Visual style and spacing: src/styles.css

Model selection: server-side GEMINI_MODEL; local development uses ignored .dev.vars.

A practice to reuse

When Gemini 3.8 Flash returned repeated upstream 503 high-demand errors, the evidence pointed to provider availability rather than the request contract: the same Interactions API and validation path succeeded with 3.6 Flash. The model default and rationale were recorded in devpost/spec.md and devpost/checklist.md, while the model remained configurable and no fallback logic was added. On another project, isolate a failure with a controlled comparison, change only the decision the evidence supports, and record the reason in the plan.

Run locally: npm run dev -- --host 127.0.0.1 (configure the local server secret in ignored .dev.vars first). Run npm test, npm run typecheck, and npm run build for checks.
